# AI 产品功能验收 — 视觉验证协议

## 概述

Playwright 执行操作并截图。多模态 AI Agent（叶欣 / GPT 5.6）通过 `read` 工具读取截图，判断功能是否符合预期。

**核心原则：代码不做视觉判断，Agent 不做操作执行。**

## 验收流程

```
Playwright 跑测试 → 操作 + 截图 → 输出到 tests/ai-e2e/output/
    → 收集截图路径 + 期望描述
    → sessions_send 发给验证 Agent（叶欣）
    → Agent 用 read 工具看图
    → 输出 PASS/FAIL + 理由
```

## 代码层输出（每次测试运行后）

代码只负责输出以下内容，**不做任何判断**：

```
场景：{场景名称}
操作：{具体操作描述}
期望：{截图里应该看到什么}
截图：
  - 操作前：{path}
  - 操作后：{path}
技术状态：{console.error 数量} 错误 / 页面崩溃？
```

## Agent 验收 Prompt 模板

### 发给叶欣的消息格式

```
请验收以下 tapword-translator 扩展的功能截图。

## 场景
{场景名称}

## 操作
{具体操作描述}

## 期望结果（代码不知道截图里有什么，这是给 Agent 的判断依据）
{详细描述操作后截图应该看到什么：
  - 应该出现什么元素？
  - 元素在什么位置？
  - 元素里有什么内容？
  - 页面其他内容是否受影响？
  - 不应该出现什么？}

## 截图
| 类型 | 路径 | 说明 |
|------|------|------|
| 操作前 | {before.png} | 操作前的页面基线状态 |
| 操作后 | {after.png} | 操作后的结果状态 |

## 验证要求
对操作后截图逐项检查：
1. 操作前 vs 操作后：变化是否符合预期？
2. 翻译 UI 是否出现？内容是否完整可读？
3. 页面布局是否被破坏？（遮挡、重叠、截断）
4. 页面其他内容是否受影响？
5. 样式是否合理？（字体、颜色、位置）

## 输出格式
| 检查项 | 判定 | 理由 |
|--------|------|------|
| 变化符合预期 | ✅/❌ | ... |
| 翻译 UI 完整 | ✅/❌ | ... |
| 布局无破坏 | ✅/❌ | ... |
| 无副作用 | ✅/❌ | ... |
| 样式合理 | ✅/❌ | ... |

最终结论：✅ PASS / ❌ FAIL
理由：{一句话总结}
```

### 示例：单击翻译

```
请验收 tapword-translator 扩展的「单击翻译」功能。

## 场景
单击翻译 — 点击高亮词触发翻译弹窗

## 操作
在测试页面中，点击带有黄色高亮背景的词 "important"。

## 期望结果
点击后，在 "important" 词的附近（上方或右侧）应该出现一个翻译弹窗。
弹窗内有该词的中文翻译（如 "重要的"）。
弹窗有明显边框和背景色，与页面内容区分明显。
页面其他文字和布局不受影响，只多出一个弹窗。

## 截图
| 操作前 | tests/ai-e2e/output/click-before-xxx.png | 页面有黄色高亮词 "important" |
| 操作后 | tests/ai-e2e/output/click-after-xxx.png | 点击后的页面状态 |

## 验证要求
1. 操作后截图：高亮词 "important" 旁出现翻译弹窗
2. 弹窗内有可读的中文翻译文字
3. 弹窗不遮挡或破坏页面其他内容
4. 页面布局整体正常
```

### 示例：划词翻译

```
请验收 tapword-translator 扩展的「划词翻译」功能。

## 场景
划词翻译 — 选中文字后点击翻译图标

## 操作
在测试页面中，选中词 "translation"，然后触发 mouseup 事件。

## 期望结果
选中后，在选中文字附近出现一个浮动翻译图标（小图标，通常在选区右上角）。
点击该图标后，在选中文字附近出现翻译弹窗，内有中文翻译。
弹窗不遮挡或破坏页面其他内容。

## 截图
| 操作前 | tests/ai-e2e/output/drag-before-xxx.png | 页面有目标词 "translation" |
| 操作后 | tests/ai-e2e/output/drag-after-xxx.png | 选中并点击图标后的状态 |

## 验证要求
1. 操作后截图：选中文字附近可见翻译弹窗
2. 弹窗内有可读的中文翻译文字
3. 弹窗不遮挡或破坏页面其他内容
4. 页面布局整体正常
```

## 与代码层的协作边界

| 代码层 | Agent 层 |
|--------|----------|
| 执行操作 | 判断结果 |
| 捕获截图 | 读取截图 |
| 检查 console.error | 检查视觉效果 |
| 检测页面崩溃 | 判断布局完整性 |
| 输出截图路径 | 输出 PASS/FAIL + 理由 |
| **不做视觉判断** | **不做操作执行** |

## 快速失败（Fast Fail）

如果代码层检测到以下情况，直接标记失败，**不截图、不交给 Agent**：
- 页面崩溃（console.error 包含致命错误）
- 浏览器进程异常退出
- 扩展加载失败（Service Worker 未启动）

这些情况不需要 Agent 看图——技术层面已失败。
