# Issue 选择规则

## 自动选择（不需要老板决策）

以下类型的 issue 可以自动认领并执行：

### ✅ 可以自动处理
- 明确的 bug（有复现步骤、有预期行为）
- 纯前端 UI 改进（样式、布局、交互）
- 纯后端 API 改进（新增字段、参数校验）
- 新增翻译目标语言（pattern 与 #23 相同）
- 文档更新、README 改进
- 配置优化（默认值、环境变量）
- 小型重构（提取公共函数、消除重复代码）

### ❌ 需要老板决策（跳过）
- 新平台支持（Safari、移动端 Firefox、Edge 等）
- 架构重构（模块拆分、数据模型变更）
- 涉及付费/API 密钥/第三方服务变更
- 涉及用户数据迁移或存储方案变更
- Issue 评论中有争议或需求不明确
- 涉及多产品线联动的大功能
- 涉及品牌/设计/市场策略的变更

## 优先级排序

1. **P0 — 用户阻塞性 bug**：翻译完全不能用、插件崩溃
2. **P1 — 功能性 bug**：部分场景翻译失败、样式错乱
3. **P2 — 小型功能增强**：明确 scope 的 enhancement
4. **P3 — 体验优化**：交互改进、文案优化
5. **P4 — 技术债务**：代码清理、测试补充
