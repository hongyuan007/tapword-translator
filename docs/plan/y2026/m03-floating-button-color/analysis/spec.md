# Floating Button Color — Configurable Icon Color

**Date**: 2026-03-20  
**Status**: Draft  
**Scope**: Make the floating button's brand color (`#ED6D8F`) user-configurable via the Options page.

---

## 1. Current State Analysis

### 1.1 Where `#ED6D8F` (and derived colors) appear

All color occurrences live in **`src/12_floating_button/ui/iconVariants.ts`**, inside the `ICON_VARIANTS` record:

| Variant | Usage | Color(s) | Notes |
|---------|-------|----------|-------|
| **V1** | `fill="#ED6D8F"` on `<circle>` | `#ED6D8F` | Pink circle background, white T |
| **V2** | `<linearGradient>` with two stops + shadow | `#FF8EA9` (light), `#D95377` (dark), `#a0294c` (flood shadow) | All three are **derived** from the brand pink; no raw `#ED6D8F` |
| **V3** | `fill="#ED6D8F"` on `<circle>` | `#ED6D8F` | Same pattern as V1 |
| **V4** | `fill="#ED6D8F"` on T `<path>` | `#ED6D8F` | No background circle — pink is on the T itself |
| **V5** | `fill="#ED6D8F"` on T `<path>` **and** large star `<path>` | `#ED6D8F` × 2, **`#FFB020`** (gold star) | Gold star must **NOT** be replaced |
| **V6** | `fill="#ED6D8F"` on `<circle>` | `#ED6D8F` | Circle bg; all other fills are `#ffffff` |

### 1.2 How SVGs are stored and rendered

- **Storage**: `ICON_VARIANTS` is a `Record<IconVariant, string>` — static SVG markup strings keyed by variant identifier (`v1`–`v6`).
- **Content script rendering**: `FloatingButtonRenderer.create(iconVariant)` sets `mainButton.innerHTML = ICON_VARIANTS[iconVariant]`.
- **Options page preview**: `initIconVariantPicker()` in `src/4_options/index.ts` iterates `ICON_VARIANT_KEYS` and injects each SVG string into a `<span class="icon-preview icon-preview--variant">`.

### 1.3 How config works

- **Type**: `FloatingButtonConfig` in `src/12_floating_button/types.ts` — currently has `enabled`, `position`, `disabledSites`, `iconVariant`.
- **Storage key**: `floatingButtonConfig` in `chrome.storage.local`.
- **Default**: `DEFAULT_CONFIG` in `src/12_floating_button/constants.ts`.
- **Config store**: `FloatingButtonConfigStore` in `src/12_floating_button/config/FloatingButtonConfigStore.ts` — handles load/save/sync via `chrome.storage.onChanged`.
- **Config change flow**: `FloatingButtonManager.handleConfigChanged()` checks if `iconVariant` changed; if so, calls `recreateButton()` which destroys and rebuilds the entire DOM tree.

### 1.4 Options page patterns (reference)

- **Icon variant picker**: Radio buttons dynamically generated by JS, stored directly to `floatingButtonConfig` in `chrome.storage.local` (bypasses `UserSettings` / `settingsManager`).
- **Word Underline Color**: Uses a **custom-select dropdown** component (`<div class="custom-select-wrapper" data-setting="wordUnderlineColorV2">`). Each option has a color-dot preview + i18n label. Selection triggers `settingsManager.saveSetting()` which writes to `UserSettings` in `chrome.storage.sync`.

## 2. Proposed Changes

### 2.1 New config field

Add `iconColor: string` to `FloatingButtonConfig`:

```typescript
export interface FloatingButtonConfig {
    enabled: boolean;
    position: number;
    disabledSites: string[];
    iconVariant: IconVariant;
    /** Brand color hex for the icon (default: '#ED6D8F') */
    iconColor: string;  // NEW
}
```

**Storage**: Persisted inside the existing `floatingButtonConfig` key in `chrome.storage.local` (same as `iconVariant`).  
**Default value**: `'#ED6D8F'` (current hardcoded pink).

### 2.2 SVG color replacement strategy

#### Approach evaluation

| Approach | Pros | Cons | V2 gradient handling |
|----------|------|------|----------------------|
| **A. Template functions** | Full control; handles all edge cases; type-safe | Requires rewriting `ICON_VARIANTS` from strings to functions; slightly more verbose | ✅ Derive lighter/darker stops from input color via HSL math |
| **B. Runtime string replace** | Minimal code change; keep SVGs as-is | Cannot handle V2 (gradient uses derived colors, not `#ED6D8F`); fragile if SVG content changes | ❌ Fails for V2 |
| **C. CSS custom properties** | Clean separation of style/content | Inline SVG `fill` attributes override CSS; `currentColor` only works for single-color; gradients cannot use CSS vars in all browsers | ❌ Fails for V2 gradients |

#### Recommended: **Approach A — Template functions**

Convert `ICON_VARIANTS` from `Record<IconVariant, string>` to `Record<IconVariant, (color: string) => string>`.

Each function receives the brand `color` hex and returns the complete SVG string with the color interpolated. For V2, a helper function derives gradient stops:

```typescript
// Color utility (add to iconVariants.ts or a shared util)
function lightenHex(hex: string, amount: number): string { /* HSL lighten */ }
function darkenHex(hex: string, amount: number): string  { /* HSL darken  */ }

export const ICON_VARIANTS: Record<IconVariant, (color: string) => string> = {
    v1: (color) => `<svg ...><circle ... fill="${color}" />...`,
    v2: (color) => {
        const light = lightenHex(color, 0.12);
        const dark  = darkenHex(color, 0.15);
        const shadow = darkenHex(color, 0.35);
        return `<svg ...><linearGradient ...>
            <stop offset="0%" stop-color="${light}" />
            <stop offset="100%" stop-color="${dark}" />
        </linearGradient>
        <filter ...><feDropShadow ... flood-color="${shadow}"/></filter>...`;
    },
    v4: (color) => `<svg ...><path ... fill="${color}" />...`,  // T itself
    v5: (color) => `<svg ...><path ... fill="${color}" />       // T
                           <path ... fill="${color}" />          // big star
                           <path ... fill="#FFB020" />...`,      // gold star kept
    // etc.
};
```

**Why this is best**: V2's gradient requires computing lighter (`#FF8EA9`) and darker (`#D95377`) shades from the base color. Only a function approach can do this cleanly. Runtime string-replace can't find colors that don't appear literally, and CSS vars don't penetrate inline SVG `fill` attributes.

#### Color utility requirements

A small HSL-based color manipulation utility is needed:
- `hexToHsl(hex: string): { h: number; s: number; l: number }`
- `hslToHex(h: number, s: number, l: number): string`
- `lightenHex(hex: string, amount: number): string` — increase lightness
- `darkenHex(hex: string, amount: number): string` — decrease lightness

These can be placed in a new file `src/12_floating_button/ui/colorUtils.ts` (kept module-private; not exported from the module index).

Add a **custom-select dropdown** (identical pattern to "Word Underline Color") below the icon variant picker:

```html

        <span class="custom-select-arrow"></span>

      <div class="custom-select-options">
        <!-- Color preset options (see §2.5) -->
      </div>
    </div>
  </div>
```

**Key difference from Word Underline Color**: This setting is stored in `floatingButtonConfig` (chrome.storage.local), NOT in `UserSettings` (chrome.storage.sync). The dropdown **cannot** use the generic `data-setting` → `settingsManager.saveSetting()` pipeline. Instead, it needs its own handler that:
1. Reads the existing `floatingButtonConfig` from `chrome.storage.local`
2. Updates `iconColor`
3. Writes back to `chrome.storage.local`

This follows the same pattern as the existing `selectIconVariant()` function in `src/4_options/index.ts`.

### 2.4 Icon variant picker preview update

When the user changes the button color, the icon variant picker previews must also update to reflect the new color. This requires:
1. Re-rendering all `<span class="icon-preview icon-preview--variant">` elements with the new color.
2. The `initIconVariantPicker()` function should accept a `color` parameter and use `ICON_VARIANTS[key](color)` instead of `ICON_VARIANTS[key]`.
3. A shared `refreshIconVariantPreviews(color: string)` function that updates all preview thumbs.

## 4. Risks / Edge Cases

### 4.1 V2 gradient color derivation

V2 currently uses these hardcoded derived colors:
- Light stop: `#FF8EA9` (roughly +12% lightness from `#ED6D8F`)
- Dark stop: `#D95377` (roughly −15% lightness)
- Shadow: `#a0294c` (roughly −35% lightness)

**Risk**: If the user picks a very light or very dark base color, the gradient range may collapse (e.g., lighten on white = still white).  
**Mitigation**: Clamp lightness values; ensure at least 10% delta between gradient stops. Test with edge-case colors (#FFFFFF, #000000, saturated primary colors).

### 4.2 V4 — pink fill on T (no background circle)

V4 applies the brand color to the T glyph itself. Replacing it with a very light color (e.g., `#FFFFFF`) would make the T invisible on the white pill button background.  
**Mitigation**: Document this as a known limitation. Alternatively, consider adding a subtle outline/shadow to V4's T when lightness > 85%.

### 4.3 V5 — pink T + gold star

V5 has two `fill="#ED6D8F"` paths (T and big star) and one `fill="#FFB020"` path (small gold star). Only the pink paths should be color-replaced.  
**Mitigation**: The template function approach handles this cleanly — the gold star hex is hardcoded in the template, only `color` parameter slots replace pink.

### 4.4 SVG filter/gradient ID collisions

V2 uses `id="v2-grad"` and `id="v2-shadow"`. If multiple instances of the button exist (unlikely in production, possible during development or in options page previews), IDs would collide.  
**Mitigation**: Currently not a problem — only one instance exists per page. For the options page preview, each variant card renders a different variant, so V2 only appears once. If needed, unique ID prefixes can be added as a future hardening step (e.g., `id="tw-fab-v2-grad-${instanceId}"`).

### 4.5 Type change of `ICON_VARIANTS` — breaking callers

Changing from `string` to `(color: string) => string` is a **breaking type change**. All call sites must be updated:
- `FloatingButtonRenderer.create()` — line `mainButton.innerHTML = ICON_VARIANTS[iconVariant]`
- `initIconVariantPicker()` in `src/4_options/index.ts` — line ``${iconVariantsModule.ICON_VARIANTS[key]}``

Both must call the function with the current color. There are only these two call sites.

### 4.6 Migration — existing users

Users who upgrade will not have `iconColor` in their stored config. The `FloatingButtonConfigStore.load()` method already spreads `{ ...DEFAULT_CONFIG, ...stored }`, so the default `'#ED6D8F'` will be applied automatically. **No migration needed.**
