### Task Objectives

This task **attempted to** address a language detection inaccuracy affecting the primary user demographic (Chinese users reading English web content). The specific symptom was that `chrome.i18n.detectLanguage`, when called with a short selected word (e.g., "nominated", 9 chars), returned statistically plausible but incorrect language codes (e.g., "la" for Latin instead of "en" for English). This caused the downstream translation API to receive an incorrect `sourceLanguage`, potentially degrading translation quality.

Two changes were made in an attempt to mitigate this root cause:

1. **Change 1** — In `TranslationPipeline.ts`, the input text used to detect `selectionLang` was changed from `sanitizedText` (the selected word itself) to `textForRouting` (the surrounding block paragraph text), which is the same input used for `routingLang`.
2. **Change 2** — In `languageDetector.ts`, a fast-path early-return heuristic was added: short printable-ASCII text (≤10 chars) is assumed to be English without calling the Chrome API.
