## 2. Proposed Type Changes

### 2.1 New Interface

```typescript
/** A user-configured custom AI provider (OpenAI-compatible) */
export interface CustomAiProvider {
    /** Auto-generated ID, e.g. "custom_abc123" (timestamp-based or nanoid) */
    id: string
    /** User-given display name */
    name: string
    /** OpenAI-compatible base URL */
    endpoint: string
    /** API key */
    apiKey: string
    /** Model name */
    model: string
}
```

### 2.2 Updated TranslationProvider Type

Remove `"customApi"` from the union (it is now identified by ID string at runtime):

```typescript
// BEFORE
export type TranslationProvider = "official" | "customApi" | "microsoftFree" | "googleFree"

// AFTER — fixed provider literals only; custom IDs are plain strings
export type FixedTranslationProvider = "official" | "microsoftFree" | "googleFree"
// Provider value at runtime: FixedTranslationProvider | string (custom ID like "custom_abc123")
```

> **Design note**: Keep `TranslationProvider` as a loose `string` type for storage fields to avoid widespread casting. A type guard helper `isCustomProvider(id, providers)` should be added to `0_common/utils/`.

### 2.3 UserSettings — Before / After

**Remove**:
```typescript
translationProvider: TranslationProvider
customApi: CustomApiSettings
```

**Add**:
```typescript
/** Provider used for full-page (whole-page) translation */
fullPageTranslationProvider: string       // default: "official"
/** Provider used for word/phrase (tap-word) translation */
wordTranslationProvider: string           // default: "official"
/** Array of user-configured custom AI providers */
customProviders: CustomAiProvider[]       // default: []
```

**Remove `CustomApiSettings` interface** (replaced by `CustomAiProvider`).

### 2.4 Updated DEFAULT_USER_SETTINGS

```typescript
// Remove:
translationProvider: "official",
customApi: { baseUrl: "", apiKey: "", model: "" },

// Add:
fullPageTranslationProvider: "official",
wordTranslationProvider: "official",
customProviders: [],
```

## 3. Storage Changes (storageManager.ts)

### 3.1 normalizeUserSettings() Changes

**Remove**:
- The `mergedCustomApi` + `normalizedCustomApi` block
- The `settings.customApi` explicit key in the merged result  
- The `isCommunityEdition && settings.translationProvider === undefined` logic

**Add**:
```typescript
// Normalize customProviders: ensure array, filter malformed entries
const normalizedCustomProviders: CustomAiProvider[] = (
    Array.isArray(settings.customProviders) ? settings.customProviders : []
).filter(
    (p) => p && typeof p.id === "string" && typeof p.endpoint === "string"
).map((p) => ({
    id: p.id,
    name: (p.name || "").trim() || "Custom Provider",
    endpoint: (p.endpoint || "").trim(),
    apiKey: (p.apiKey || "").trim(),
    model: (p.model || "").trim(),
}))

// Validate provider values — fall back to "official" if unknown id
const validFixedProviders = ["official", "microsoftFree", "googleFree"]
function resolveProvider(value: string | undefined, providers: CustomAiProvider[]): string {
    if (!value) return "official"
    if (validFixedProviders.includes(value)) return value
    if (providers.some((p) => p.id === value)) return value
    return "official"
}

fullPageTranslationProvider: resolveProvider(settings.fullPageTranslationProvider, normalizedCustomProviders),
wordTranslationProvider: resolveProvider(settings.wordTranslationProvider, normalizedCustomProviders),
customProviders: normalizedCustomProviders,
```

**Community edition default change**: Instead of defaulting to `"customApi"`, default the first installed provider (if any) or `"official"` (community can still use official if user sets up API key through the new flow).

### 3.2 Migration Logic

Add a migration block inside `normalizeUserSettings()` that runs once for existing users:

```typescript
// [Migration] Migrate legacy translationProvider + customApi → new fields
if (
    settings.translationProvider !== undefined &&
    settings.fullPageTranslationProvider === undefined
) {
    // Map old "customApi" to first discovered custom provider, or "official"
    const legacyProvider = settings.translationProvider as string
    const migratedProvider = validFixedProviders.includes(legacyProvider)
        ? legacyProvider
        : "official"  // Can't recover custom ID from old data — reset to official

    // If old customApi had data, create a migrated CustomAiProvider entry
    const legacyApi = (settings as any).customApi as CustomApiSettings | undefined
    if (legacyApi?.apiKey && legacyApi?.baseUrl && legacyApi?.model) {
        const migratedEntry: CustomAiProvider = {
            id: `custom_migrated_${Date.now()}`,
            name: "Migrated Custom API",
            endpoint: legacyApi.baseUrl,
            apiKey: legacyApi.apiKey,
            model: legacyApi.model,
        }
        // Prepend to any already-present providers
        normalizedCustomProviders.unshift(migratedEntry)

        // If legacy provider was "customApi", point both selectors to migrated entry
        if (legacyProvider === "customApi") {
            settings.fullPageTranslationProvider = migratedEntry.id
            settings.wordTranslationProvider = migratedEntry.id
        }
    }

    // Write back resolved defaults if still unset
    if (settings.fullPageTranslationProvider === undefined) {
        settings.fullPageTranslationProvider = migratedProvider
    }
    if (settings.wordTranslationProvider === undefined) {
        settings.wordTranslationProvider = migratedProvider
    }
}
```

## 4. Routing Logic Changes

### 4.1 Helper Function (new utility, e.g. src/0_common/utils/providerResolver.ts)

```typescript
import type { UserSettings, CustomAiProvider } from "@/0_common/types"
import type { LLMConfig } from "@/8_generate/types/GenerateTypes"
import { CUSTOM_API_FIXED_PARAMS } from "@/0_common/constants/customApi"

export type ProviderKind =
    | { kind: "official" }
    | { kind: "microsoftFree" }
    | { kind: "googleFree" }
    | { kind: "customAi"; provider: CustomAiProvider }
    | { kind: "unknown" }

export function resolveProviderKind(providerId: string, settings: UserSettings): ProviderKind {
    switch (providerId) {
        case "official": return { kind: "official" }
        case "microsoftFree": return { kind: "microsoftFree" }
        case "googleFree": return { kind: "googleFree" }
        default: {
            const found = settings.customProviders.find((p) => p.id === providerId)
            return found ? { kind: "customAi", provider: found } : { kind: "unknown" }
        }
    }
}

export function buildLlmConfig(provider: CustomAiProvider): LLMConfig {
    return {
        apiKey: provider.apiKey,
        baseUrl: provider.endpoint,
        model: provider.model,
        temperature: CUSTOM_API_FIXED_PARAMS.temperature,
        maxTokens: CUSTOM_API_FIXED_PARAMS.maxTokens,
        timeout: CUSTOM_API_FIXED_PARAMS.timeout,
    }
}
```

## 9. Risks and Edge Cases

### 9.1 Migration of Old Settings
- **Risk**: Existing users lose their `customApi` config silently.
- **Mitigation**: The migration block in `normalizeUserSettings()` reads old `customApi` data and creates a `CustomAiProvider` entry automatically. Old `translationProvider: "customApi"` users are redirected to the migrated provider ID.
- **Risk**: `chrome.storage.sync` quota — `customProviders` array adds size. Each provider is ~300 bytes; 10 providers ≈ 3KB. Total sync storage is 100KB — acceptable.

### 9.2 Empty `customProviders` Array
- Popup provider select should show the `__add_provider` sentinel option when `customProviders.length === 0` (after the three fixed options).
- Selecting `__add_provider` opens the Options page; the select reverts to previous value.
- Both `fullPageTranslationProvider` and `wordTranslationProvider` default to `"official"` if empty — safe.

### 9.3 Invalid Provider ID Stored
- If a user's `customProviders` entry is deleted but `fullPageTranslationProvider` still holds its ID, `resolveProviderKind()` returns `{ kind: "unknown" }`.
- Handlers must treat `kind: "unknown"` as fallback to `"official"` with a warning log, **not** a crash.
- The normalization in `storageManager.normalizeUserSettings()` also catches and resets stale IDs.

### 9.6 AutoCandidates and Custom Providers
