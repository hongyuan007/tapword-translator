**Date:** 2026-05-10  
**Author:** Research Agent

## 1. Goal

Implement full-text batch translation for the `customApi` provider in the plugin. When the user has configured a custom LLM provider and triggers full-page translation, the plugin's background worker should call the user's LLM directly (using the same XML-segment batch strategy as the cloud backend), instead of calling the official TapWord API endpoint.

### 2.3 Prompt Files (exact content)

**System Prompt** — `resources/generate/full_text_batch/system_prompt.txt`

```
You are a professional translator.

## Task
Translate the text content within each <segment> tag from the source language to the target language.

## Rules
- Each input <segment> has a unique id attribute — preserve it exactly
- Translate ONLY the text inside each <segment> tag
- Preserve the exact XML structure: same tag names, same id values, same order
- NEVER translate, modify, or remove the XML tags or their attributes
- Each segment is independent — translate them separately
- If a segment is already in the target language, return it unchanged
- Preserve numbers, proper nouns, URLs, code snippets, and special formatting
- Return a segment unchanged when translation would not add meaning, especially for standalone social media handles, usernames, person names, brand names, product names, URLs, email addresses, file names, code snippets, commands, IDs, hashes, ticker symbols, emoji, or punctuation-only text
- When returning a segment unchanged, preserve the exact original characters inside the segment; do not add, remove, transliterate, localize, or reformat anything
- Do not force transliteration, explanation, or localization for standalone proper nouns or identifiers
- If a segment mixes natural language with non-translatable tokens, translate the natural-language text and preserve the non-translatable tokens exactly

## Output Format
Return ONLY the translated segments, one per line, using the same XML structure:
<segment id="0">translated text</segment>
<segment id="1">translated text</segment>

## Critical Rules
- Output EXACTLY the same number of <segment> tags as the input
- Each <segment> id in the output must match the corresponding input id
- Do NOT add any text, explanation, or commentary outside <segment> tags
- Do NOT wrap output in code blocks, markdown, or JSON
- Do NOT add a wrapping <segments> root element
```

**User Prompt Template** — `resources/generate/full_text_batch/user_prompt_template.txt`

```
# Source Language
${sourceLanguage}

# Target Language
${targetLanguage}

# Number of Segments
${count}

# Text to Translate
${text}
```

**Template variables:**
- `${sourceLanguage}` — human-readable name (e.g. "English")
- `${targetLanguage}` — human-readable name (e.g. "Chinese")
- `${count}` — number of segments (integer as string)
- `${text}` — XML-assembled segments

**Few-shot examples** — two language variants exist:
- `resources/generate/full_text_batch/en/fewshot.json` (3 exchange pairs, covers proper nouns / code / emoji edge cases)
- `resources/generate/full_text_batch/zh/fewshot.json` (3 exchange pairs, same content with Chinese zh instructions)

Both are arrays of `{ role: "user" | "assistant", content: string }` objects.

### 2.6 XML Input Format

Each text is wrapped in numbered XML segments with XML-escaped content:

```xml
<segment id="0">First text&amp;here</segment>
<segment id="1">Second text &lt;tag&gt;</segment>
```

Escape rules: `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`

### 2.7 XML Output Parsing (Dual Strategy)

**Primary — iterative tag-by-tag extraction:**
1. Find `<segment id="` prefix
2. Extract integer id
3. Find `>` for content start, `</segment>` for content end
4. Unescape content: `&lt;` → `<`, `&gt;` → `>`, `&amp;` → `&`
5. Store at `result[id]`
6. Throw if `matchCount !== expectedCount`

**Fallback — regex:**
```
/<segment id="(\d+)">([\s\S]*?)<\/segment>/g
```
Same unescape + count validation.

### 2.8 Input / Output Format

**Input:**
```typescript
interface FullTextBatchRequest {
    texts: string[]
    sourceLanguage: string  // language code e.g. "en", "zh-CN"
    targetLanguage: string
}
```

**Output:**
```typescript
interface FullTextBatchResult {
    translations: string[]  // same length and order as input texts
    usage: TokenUsage | null
}
```

### 4.2 New: `src/8_generate/services/FullTextBatchGenerationService.ts`

New service file. Structure mirrors `AutoCandidatesGenerationService` but outputs `string[]` instead of candidates.

**Required behavior:**
1. Constructor takes `LLMConfig`, creates `OpenAICompatibleClient` with `maxTokens` overridden to `10000`
2. `initialize()` loads `systemPrompt` and `userPromptTemplate` using `promptLoaderModule.loadSystemPrompt(TASK_FULL_TEXT_BATCH)` and `promptLoaderModule.loadUserPromptTemplate(TASK_FULL_TEXT_BATCH)`
3. `translateBatch(request: { texts: string[], sourceLanguage: string, targetLanguage: string }): Promise<string[]>`:
   - Calls `languageUtilsModule.getLanguageNames(sourceLanguage, targetLanguage)` for prompt variables
   - Assembles XML: `texts.map((text, i) => \`<segment id="${i}">${escapeXml(text)}</segment>\`).join("\n")`
   - Renders user prompt via `renderTemplate(userPromptTemplate, { sourceLanguage: sourceName, targetLanguage: targetName, count: String(texts.length), text: xmlInput })`
   - Loads fewshot: `await promptLoaderModule.loadFewshot(TASK_FULL_TEXT_BATCH, targetLanguage)`
   - Builds messages: `[{ role: "system", content: systemPrompt }, ...fewshotMessages, { role: "user", content: userPrompt }]`
   - Calls `await this.client.generateText(messages)` (see 4.3 below — new `generateText` method that does NOT set json response_format)
   - Parses XML response using dual strategy (primary iterative + regex fallback)
   - Returns `string[]` of length `texts.length`
4. XML escaping: `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`
5. XML unescaping: `&lt;` → `<`, `&gt;` → `>`, `&amp;` → `&`
6. Parsing error: throw `Error("XML segment count mismatch: expected N, got M")`

**Export:** `FullTextBatchGenerationService` class + `generateFullTextBatch` convenience function.

```typescript
if (settings.translationProvider === "customApi") {
    const customApi = settings.customApi
    const apiKey = customApi.apiKey.trim()
    const baseUrl = customApi.baseUrl.trim()
    const model = customApi.model.trim()

    if (!apiKey || !baseUrl || !model) {
        sendResponse({
            success: false,
            error: "Custom API configuration is incomplete (missing apiKey, baseUrl, or model)",

        return

        apiKey,
        baseUrl,
        model,
        temperature: CUSTOM_API_FIXED_PARAMS.temperature,
        maxTokens: MAX_TOKENS_FULL_TEXT_BATCH,    // override to 10000
        timeout: CUSTOM_API_FIXED_PARAMS.timeout,
    }

    const translations = await generateModule.generateFullTextBatch(data.texts, data.sourceLang, data.targetLang, llmConfig)

    sendResponse({ success: true, translations })
    return
}
```

## 5. Implementation Notes

### 5.1 `generateFullTextBatch` Convenience Function Signature

```typescript
export async function generateFullTextBatch(
    texts: string[],
    sourceLanguage: string,
    targetLanguage: string,
    config: LLMConfig
): Promise<string[]>
```

Internally: create service, call `initialize()`, call `translateBatch()`, return `string[]`.

### 5.2 `OpenAICompatibleClient` maxTokens Override

The `OpenAICompatibleClient` currently reads `maxTokens` from the constructor config. For full_text_batch, pass `maxTokens: 10000` in the `LLMConfig`. The new `generateText()` method uses `this.maxTokens` from the instance (inherited from constructor config), so passing `maxTokens: 10000` in the config is sufficient — no per-call override needed.

### 5.3 Error Handling in Handler

Wrap the customApi branch in the same try/catch as the official path. On error, call:
```typescript
sendResponse({ success: false, error: error instanceof Error ? error.message : String(error) })
```
No quota error type needed for customApi.

### 5.4 `renderTemplate` Compatibility

The plugin's `templateRenderer.ts` uses `${variable}` syntax (same as backend). The template variables are:
- `sourceLanguage` → sourceName (human-readable)
- `targetLanguage` → targetName (human-readable)
- `count` → `String(texts.length)`
- `text` → the assembled XML string

### 5.5 Fewshot Loading

The plugin `promptLoader.loadFewshot(taskName, language)` normalizes language code (e.g. `"zh-CN"` → `"zh"`), tries `resources/8_generate/full_text_batch/zh/fewshot.json`, falls back to `en/fewshot.json`. Only `en` and `zh` fewshot variants need to be shipped initially (matching what the backend provides).

## 6. Acceptance Criteria

1. When `translationProvider === "customApi"` and user triggers full-page translation, `FullTranslateBatchHandler` calls the user's LLM instead of the official API endpoint.
2. The quota pre-check is skipped for `customApi` (already handled by the existing `isOfficialProvider` guard).
3. The returned `FullTranslateBatchResponseMessage` has `success: true` and `translations` array of the same length and order as the input `texts`.
4. If the LLM response XML is malformed or segment count mismatches, the handler returns `{ success: false, error: "..." }`.
5. If customApi config is incomplete (missing apiKey/baseUrl/model), the handler returns `{ success: false, error: "Custom API configuration is incomplete ..." }`.
6. The LLM call does **not** set `response_format: json_object` (uses plain text mode).
7. Prompt files are accessible via `chrome.runtime.getURL("resources/8_generate/full_text_batch/...")`.
8. Existing `official` provider path in `FullTranslateBatchHandler` is unaffected.
