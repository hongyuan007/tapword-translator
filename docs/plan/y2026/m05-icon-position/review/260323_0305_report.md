## 🚨 CRITICAL / 🔴 HIGH ISSUES — MUST FIX

**文件**: `src/4_options/index.html` — Appearance Settings 区域

在 iconPosition radio group 之后、Word Underline Color 设置之前，存在一个空结构：

```html
<div class="setting-item">
  </div>
  <div class="setting-control">
```

这是一个残留的 HTML 标签碎片（缺少 `setting-info` 内容、闭合后紧跟不应在此处的 `setting-control`）。这会导致：
1. 渲染出一个无内容的卡片行，破坏 UI 视觉一致性
2. 语义上 Word Underline Color 的 `setting-control` 没有被正确的 `setting-item` 包裹

**建议**: 删除这个空的 `<div class="setting-item">` 行，确保 Word Underline Color 的 `setting-item` 结构完整。

## 💡 SUGGESTIONS — NICE TO HAVE

### N-1: `computeAutoCorner` 在所有角落空间为 0 时仍返回结果

**文件**: `src/1_content/ui/iconManager.ts` — `computeAutoCorner()`

当 `rect` 贴边时（如 `spaceBelow === 0 && spaceRight === 0`），`sort` 后所有 `space` 都为 0，仍会返回 `corners[0].corner`。此时 `clampToViewport` 会把图标推到 (0,0)。

虽然功能上不会崩溃，但图标出现在页面左上角对用户来说很困惑。

**建议**: 在 `computeAutoCorner` 中增加最小空间阈值判断，或返回 `null` / 不显示图标。

### N-2: `fr.json` 的 iconPosition 条目未翻译

**文件**: `src/0_common/locales/fr.json`

```json
"popup.iconPosition.label": "Icon position",
"popup.iconPosition.tooltip": "Choose where the translation icon appears relative to selected text.",
"popup.iconPosition.bottomRight": "Bottom-right",
...
```

法语 locale 的 iconPosition 条目使用了英语原文，而 `de.json`、`ja.json`、`ko.json`、`ru.json`、`es.json` 均有对应翻译。

**建议**: 补齐法语翻译（如 "Position de l'icône" / "En bas à droite" 等）。

### N-3: Settings 变更后不需要刷新页面，但用户可能不清楚

**文件**: `src/4_options/index.html` — iconPosition radio group

iconPosition 属于实时生效的设置（content script 读取 cached settings），但 radio group 下方没有类似 "Changes take effect immediately" 或 "Refresh the page to apply" 的提示。

其他设置项（如 `popup.refreshReminder`）已有此模式。

**建议**: 考虑在 radio group 下加一行 `setting-helper` 说明即时生效，与现有 UX 模式保持一致。

## 🧠 ARCHITECTURAL & LOGIC INSIGHTS

### [设计模式] ✅ 符合项目惯例

- `IconPosition` type 使用 union type + `DEFAULT_USER_SETTINGS` 默认值，与 `IconColor`、`TriggerKey`、`NetworkRegion` 完全一致
- `iconManager.ts` 的 position 计算逻辑保持纯函数风格（`calculateCornerPosition`、`clampToViewport`、`computeAutoCorner`），无副作用，易测试
- Settings 透传路径清晰：`InputListener.handleTextSelection()` → `getCachedUserSettings()` → `iconPosition ?? "bottom-right"` → `showTranslationIcon()`

### [防御性编程] ✅ 良好

- `calculateIconPosition` 对 `rects.length === 0` 和 `rect === null` 都做了 fallback 返回 `{ top: 0, left: 0 }`
- `InputListener` 使用 `settings?.iconPosition ?? "bottom-right"` 防止 settings 未加载

### [安全性] ✅ 无问题

- 无 `innerHTML` 注入外部数据风险（SVG 内容为静态模板字符串，`colorHex` 来自内部常量 `ICON_COLORS` 映射）
- 无 `eval` / `new Function`
- locale key 全部为静态字符串

### [资源清理] ✅ 无泄漏

- `removeTranslationIcon()` 正确清理了 timeout 和 DOM 节点
- fade-out 使用 `setTimeout` + `remove()`，模式与现有实现一致

### [Hostile Environment] ⚠️ 轻微关注

图标直接 `appendChild` 到 `document.body`，依赖 `constants.CSS_CLASSES.ICON` 的 CSS 隔离。这在项目其他地方也是同样做法（翻译 tooltip 也是如此），保持了一致性。但未来如果目标网站有同名 CSS class 冲突，可能出问题——这是项目级架构决策，不在本次 PR 范围内。
