## 🟡 Nice to Have (4)

### 1. [Design Pattern] HTML `<option>` lists are still hardcoded — duplicated in 2 files

**Files:** `src/3_popup/index.html`, `src/4_options/index.html`

Both files have identical `<option>` lists for the target language `<select>`. These are now out of sync with the `TARGET_LANGUAGES` constant by nature (hardcoded vs. registry). If a new language is added, a developer must remember to update **3 places** (registry + 2 HTML files).

**Suggestion:** Consider generating these options dynamically from `TARGET_LANGUAGES` in the popup/options JS init code. Not blocking — the registry is already a big improvement, and HTML duplication is low-risk since both files are under frontend control.

### 2. [Maintainability] `LANGUAGE_CODE_MAP` duplication in BingTranslateService & MTranServerService

**Files:** `BingTranslateService.ts`, `MTranServerService.ts`

Both services have nearly identical `LANGUAGE_CODE_MAP` records (and both already include the `zh-tw → zh-Hant` mapping). Future language additions require updating both maps.

**Suggestion:** Extract a shared `TRANSLATION_CODE_MAP` into a common utility. Not urgent since the maps are stable and rarely change.

### 3. [Consistency] `languageDetector.ts` normalizeLangCode collapses all `zh-*` to `"zh"`

**File:** `src/1_content/utils/languageDetector.ts`

The `normalizeLangCode` function maps all `zh-*` variants (including `zh-TW`) to just `"zh"`. This is correct for source detection (the extension detects script, not regional variant), but it's worth a comment explaining this design decision since the rest of the codebase now explicitly differentiates `zh` and `zh-tw`.

**Status:** The code already has a clear comment in `resolveTargetLanguage` explaining `zh` ≠ `zh-tw`. This is fine — just noting for future developers.

### 4. [Minor] `languageDisplay.ts` maps `zh-tw` to `"繁體中文"` while `languages.ts` uses `"中文（繁體）"`

**Files:** `languageDisplay.ts`, `languages.ts`

Display name inconsistency: `"繁體中文"` vs `"中文（繁體）"`. Both are acceptable Chinese formulations, but for consistency, the same string should be used everywhere.

**Suggestion:** Pick one form and use it in both places. `"中文（繁體）"` (from the registry) is arguably better since it parallels `"中文（简体）"`.
