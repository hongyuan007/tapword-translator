# Dark Mode Tooltip Contrast Issue - Technical Solution Plan

Date: 2026-02-25
Scope: Issue #14 (translation tooltip text becomes unreadable on dark-mode pages)

## 1. Problem Statement

On dark-mode websites (example: Nuxt docs page), TapWord tooltip text can be rendered as black, causing very poor readability or near invisibility against dark backgrounds.

Reported page:
- https://nuxt.com/docs/4.x/getting-started/introduction

Observed symptom:
- Tooltip computed text color is `rgb(0, 0, 0)` in a dark context.

## 3. Root Cause Analysis

Current logic in `src/1_content/utils/styleCalculator.ts`:

- `calculateTooltipStyle(...)` reads selected text color (`originalColor`) from anchor/original element.
- `getHighContrastColor(originalColor)` decides tooltip color only from selected text color brightness.
- Decision rule:
  - brightness < 150 -> black tooltip text
  - brightness >= 150 -> white tooltip text

### Why this fails

The algorithm infers background indirectly from foreground color, which is not reliable.

In Nuxt dark mode, selected text can be accent green (`#00DC82`, brightness ≈ 144), which is a medium value:
- Rule classifies it as “dark-ish text on light background” and picks black.
- Actual background is dark, so black becomes low-contrast.

So the failure is not random; it is deterministic for mid-tone accent foreground colors used on dark surfaces.

---

## 4. Recommended Fix Strategy

## 4.1 Design principle

Choose tooltip text color by **actual contrast against effective background**, not by selected text brightness.

Priority:
1. Determine effective background color near selection.
2. Compute contrast scores for black and white text.
3. Choose the color with higher contrast (with WCAG-style relative luminance ratio).

## 4.2 Proposed implementation changes

### A) Add effective background resolver

File:
- `src/1_content/utils/styleCalculator.ts`

New helper (example names):
- `getEffectiveBackgroundColor(startElement: HTMLElement | null): { r,g,b,a }`

Behavior:
1. Start from `anchor ?? originalElement`.
2. Walk up ancestor chain to `document.documentElement`.
3. For each node, inspect `getComputedStyle(node).backgroundColor`.
4. Ignore fully transparent values (`transparent`, `rgba(..., 0)`).
5. Return first non-transparent color.
6. Fallback to document/body background; if still unavailable, fallback to white.

### B) Replace brightness threshold with contrast scoring

New helper (example names):
- `getReadableTextColorForBackground(bgColor): "rgb(0, 0, 0)" | "rgb(255, 255, 255)"`

Behavior:
1. Compute relative luminance for background.
2. Compute contrast ratio with black and white:
   - `contrast(black, bg)`
   - `contrast(white, bg)`
3. Return whichever ratio is higher.

This removes the magic threshold `150` and is robust to accent-color foregrounds.

### C) Integrate into existing tooltip style pipeline

Current:
- `const color = getHighContrastColor(originalColor)`

Target:
- `const effectiveBg = getEffectiveBackgroundColor(anchor ?? originalElement)`
- `const color = getReadableTextColorForBackground(effectiveBg)`

Font-size logic remains unchanged.

---

## 5. Why this approach is preferred

- Fixes root cause instead of patching specific color values.
- Works across dark themes, light themes, and custom themes.
- Handles link/accent/brand colors naturally.
- Keeps behavior deterministic and explainable.
- Minimal blast radius: isolated to tooltip color decision path.

---

## 6. Risk and Compatibility Assessment

Low-to-medium risk:
- Main change is tooltip text color decision.
- Potential edge cases are pages with layered/translucent backgrounds.

Mitigation:
- Use first non-transparent ancestor background.
- Keep safe fallback path.
- Validate with local + live e2e scenario.

Non-goals in this fix:
- No redesign of tooltip component.
- No changes to underline color or modal theme.

5. If needed, tune fallback for transparent/background-image-heavy pages.

---

## 9. Conclusion

Issue #14 is caused by a foreground-only heuristic in tooltip color selection. The robust fix is to base tooltip text color on actual background contrast at selection context. This approach directly addresses dark-mode failures on Nuxt and similar modern docs sites using accent colors on dark backgrounds.
